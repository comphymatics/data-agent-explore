主题当前方案
实体、组织、页面Canonical Entity 唯一；Hierarchy 多视图投影；组织边与 TypedReference 事实边分开。Canonical URI 与 Aggregate View URI 永不混用。
宽泛问题的入口集中 intent-aware strategy 选择最多两个 View；AggregatePageIndex 复用 Exact/BM25/Dense/Facet/RRF，按 L0/L1 富读发现成员锚点。
明确实体的入口Exact Page/Element Anchor 走 Direct；有跨语义扩展需求才合并分支。不会为使用 Hierarchy 而强制从根浏览。
分类完成度按实体适用视图计算；Metric 仅需 Analysis placement。Candidate 不使分类变为完成，也不参与强导航。
企业规范层级显式 taxonomy_nodes/edges + Evidence 可独立构建；不依赖实例同时携带多个标签。规则或候选不能覆盖受治理 taxonomy。
Coverage按 Entity × Aspect × Layer × Selector 检查证据；一个模型的字段不能满足另一个模型，Reference 不能满足 Environment 要求。
跨层 BindingIdentityBinding、SemanticMapping、StructuralRelation 分开；同名或相似度不能证明现网身份，Overlay 不回写全局快照。
增量与状态组织贡献、受影响分支/祖先与相关索引增量更新；resume 固定 query/requirements、IndexVersion 和 serving version。不是无限自主循环。
评测与生产Dataset Builder 只产 DRAFT；Gold/Alias/Scorer 独立，禁止进入生产 Context 或检索配置。正式 Benchmark 与 Hierarchy ablation 分开。

仍待验证

企业真实材料与 taxonomy 审核、MetaOne 原始 payload/认证/分页联调、多义问题 Precision、大规模性能与 token 成本。样例成功不代表现网就绪。

本系统不是 Ontology，也不做通用 chunk-RAG；Graph 仅供机器使用。Explore 返回上下文，最终 SQL、模型设计或分析结论属于后续消费者。

LLM 在什么位置？

Parser-first：结构解析应确定性完成。可选 LLM 用于受治理的候选提取/组织选择，以及查询路由和证据片段选择；都有固定输出边界。它不能自由遍历 Graph、改写 Coverage、确认身份或提升候选为事实。Dense 在查询召回中使用，本轮没有逐实体 Dense taxonomy classification。
